# ZzzHe TMA Analysis 1.1.4

本版重点减少计算期间的界面阻塞，并复用已经校验的默认设置。

- 2,000 点及以上曲线的平滑、信号选择与求导在后台执行。小数据保持直接完成的交互；算法、单位、数据界限、最小二乘输入和运算顺序保持一致。
- 后台任务只使用独立数据快照，不接触界面对象，也不复制整份撤销历史。使用一个后台计算线程，每个文件只保留最新待执行任务，总等待队列有上限。短小 NumPy 运算期间定期让出执行时间，改善 Windows 界面响应。
- 取消、右上角 X 或退出主程序立即停止接收结果，不等待计算结束。关闭文件、修改单位、曲线、数据界限或坐标设置后，过期结果不会覆盖新状态；错误和取消不会增加撤销记录。
- 信号计算完成后保留自定义 X 的运算缓存，避免第一次重绘再次在界面线程求导。只合并目标文件的曲线，保留其它文件的编辑，以及后台更新的 m 数据。
- 默认设置以文件指纹校验并缓存，批量导入共享一次读取；外部替换、删除、损坏和恢复仍能检测。每条曲线得到独立的设置对象。
- 默认设置使用有次数上限的原子保存，保留同步落盘和旧文件保护；权限错误及时返回，避免临时文件创建反复重试。

同机真实 Qt 界面、12,000 点合成曲线的七次测试中位数：

| 操作 | 原同步方式最长界面停顿 | 本版最长界面停顿 | 点击确定返回 |
| --- | ---: | ---: | ---: |
| 平滑 | 约 476 ms | 约 111 ms | 约 12 ms |
| 二阶时间导数 | 约 635 ms | 约 273 ms | 约 9 ms |

这是界面响应改善，并非计算吞吐量加速。含重绘的完成时间分别约从 476 ms 变为 532 ms、635 ms 变为 741 ms；后台调度与让出执行时间有少量开销。两种方式的结果逐元素精确一致。默认设置 300 次读取阶段约从 217 ms 降至 29 ms；八文件整体导入仅改善约 3%，不将局部收益当作整体加速。

用户提供的 T1/T2/H 检测算法和原始文件保持不变。完整解压后运行主程序，保留整个依赖目录。沿用 ZzzHe 作者自签名及时间戳；自签名不代表 Windows 公开信任。
