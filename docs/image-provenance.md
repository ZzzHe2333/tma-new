# 图片来源辅助鉴定

PNG/TIFF 导出及分享图片采用两层标记：

1. DCT 频域标记：在均匀分布的 384 个 8×8 区块的中频系数对中嵌入 128 位固定来源标记，重复三次并多数表决。亮度作轻微调整，保留透明通道。小于 384 个区块的图片跳过频域嵌入。
2. 元数据记录：频域嵌入完成后计算像素摘要，记录软件版本、带时区的导出时间及 HMAC 校验值。EXIF 日期使用导出时刻。

工具 → 图片鉴定：

- 元数据及像素校验通过：显示记录的版本和导出时间。
- 元数据缺失但频域匹配率至少 94%：显示检测到频域来源标记，不能确认内容完整。
- 元数据存在但校验失败：提示图片内容或记录可能经过修改。
- 无可识别标记：无法确认来源。

## 来源机器码

新导出图复用软件现有的通知机器码（由当前机器硬件信息推导的16位十六进制短摘要），不写入原始硬件编号、计算机名或IP，不调用网络获取地址。机器码在进程内复用，避免每张图重复采集。

元数据中的 machine_code 纳入 HMAC 完整性校验；只在记录校验通过时展示。另在独立的归一化 DCT 系数对中嵌入16字节机器载荷：4字节格式标记、8字节机器码、4字节CRC32。提取时须来源标记检出及机器载荷格式/CRC通过，才返回机器码；失败显示未读取，不使用当前查看机器的编号补填。CRC仅用于检测误码，不用于抵御主动伪造。

测试已验证原尺寸样图在清除元数据后仍能提取机器码、模拟换机后显示导出机器码以及损坏载荷拒绝。截图、缩放、裁剪后的机器码恢复尚无普遍保证，来源标记可检出不代表机器码载荷一定可恢复。旧图不会自动获得机器码，须重新导出。当前为源码修改，尚未重新打包。

## CPU 与内网 IP

导出记录新增 environment：cpu_model（CPU型号）、lan_ip（RFC1918 IPv4内网地址）、sampled_at（采集时间）及status，随元数据一同参与完整性校验。鉴定窗口显示的是来源记录，不用查看电脑的信息补填。CPU型号和IP不占用频域载荷；元数据清除后无法恢复这两项。

应用启动时后台预热，缓存5分钟，导出时只读取进程内快照。首次采集尚未完成、失败、离线或无符合要求的内网地址时，保留空值并显示未记录；不会为等信息而阻塞界面。CPU读本地系统信息，内网地址沿用已有局域网接口选择方法，不调用公网IP查询。IP可能随VPN、网卡或网络变化；采集时间与导出时间分开记录，不能当作精确的瞬时网络归属证明。

测试覆盖元数据清除、指定样例的 JPEG quality=90 压缩、随机负样本和透明通道；不保证裁剪、缩放、重绘、强压缩或全部图片均可检出。固定频域标记可复制，内置校验密钥亦可提取，两者都不构成第三方防伪认证。频域技术会轻微改变导出图像像素，不改变测量数据或原始文件。
